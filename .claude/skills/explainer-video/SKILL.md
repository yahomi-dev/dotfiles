# 解説動画 (MP4) — 操作と仕組みを交互に見せる

成果物は **MP4 (1920×1080 / 30fps / H.264) とポスター PNG** (`--gif` で 15MB 以下の GIF も)。1 本 40〜70 秒。
見本の動画 (架空の「議事録まとめ」) が `assets/template/` にそのまま入っているので、まず `node tools/render.mjs sheet` で見本を撮って全体像をつかんでから作る。

## 手法の核

1. **画面録画をしない**。「時刻 t を渡すとその瞬間の絵を描く Web ページ」を作り、Playwright で t = 0, 1/30, 2/30 … と 1 コマずつ撮り、ffmpeg でつなぐ。乱数も実時間も使わないので、PC の速さに関係なくカクつかず、何度撮っても同じ動画になる。
2. **操作 -> 仕組み -> 操作 -> 仕組み** の交互。操作の場面はモック画面 (HTML) の上をカーソルが動いてクリック・入力し、クリックや入力に合わせてズームする。仕組みの場面は、送られた文章や数字を画面いっぱいに広げ、処理の動き (区切る・採点する・並べ替える・運ぶ) を見せる。全体の構成図は、いま関係する部分だけを合間に差し込む。
3. **数字と文は実物の記録から取る**。アプリを 1 回流した記録 (入力・途中結果・出力・かかった時間) を `data.js` (`window.RECORD`) にし、字幕も画面の文言もそこから引く。アプリ側を直したら記録を取り直して撮り直せば、字幕の数字も変わる。
4. **字幕**は画面下に小見出し (`操作 1` / `仕組み 1`、自動で番号が付く) と 1 文 (タイプライター)。字幕帯 (下 170px) にはズームした画面がかぶらない。

```
data.js (記録) + timeline.js (場面と出来事) -> engine/*.js (t の絵を描く) -> tools/render.mjs (1 コマずつ撮影 -> ffmpeg) -> MP4
```

## 0. 依頼を読む (作る前に必ず)

### 0-1. 相手と、伝えたい 1 文
- **誰が見るか**: 技術者か、専門外の人 (お客様・経営層) か。専門外なら、ファイル名や JSON を出さず、日常の言葉で書く (下の「専門外の人に見せる中身の書き方」)。
- **伝えたいことを 1 文にする** (例: 「AI は文に点を付けるだけ。区切りと並べ替えはプログラム」)。これが締め (outro) の一言になり、場面の取捨選択の基準になる。
- **その 1 文が今の実物と合っているか、作る前に確かめる**。コード・設定・ログを見る。仕組みが最近変わっていて依頼の理解が古いことがある。違えば「今の実物はこう動いている。どちらで作るか」を聞く。

### 0-2. 記録を取る
実物を 1 回流し、動画に出すものを JSON にまとめる (`record.json`)。目安の項目: 入力 (実際に送った文や値)、途中結果 (区切った単位、点数、件数、判定)、出力 (返ってきた文や画面の値)、かかった時間、呼び出した部品の名前。取れないときは止まって聞く。説明用に作った架空の例で作らない (見本の `data.js` は架空だが、本番では必ず差し替える)。

### 0-3. 場面を割る
記録を「画面で起きること (操作)」と「裏で起きること (仕組み)」に分け、時系列に交互に並べる。1 場面 1 出来事。目安は 操作 2〜3 + 仕組み 2〜4 + タイトルと締め。使う例と使わない例を決める (入力例は 1 つに絞り、分岐は見せない)。

### 0-4. 一回で伝わる頼み方 (依頼があいまいなときの聞き方。ユーザーに頼み方を聞かれたらこの形を示す)

```
【アプリ名】の解説動画を作って。見る人は【お客様 / 社内の非エンジニア / 開発者】。
伝えたいのは「【1 文】」。
形式は 操作 -> 仕組み -> 操作 -> 仕組み の交互。
操作の場面はモック画面で、カーソルが動いてクリックし、クリックや入力に合わせてズームして。
仕組みの場面は、送った【文章 / 数字】を画面いっぱいに広げて、【区切る / 採点する / 並べ替える / 渡す】動きを見せて。
全体の構成図は、該当部分だけを操作の合間に差し込んで。
数字と例は【record.json / ログ / この入力】から取って。使う例は「【例】」、使わない例は「【例】」。
画面の下に小見出しと 1 行の字幕を入れて。
```

## 1. 環境

| 必要なもの | 確認 | 無いとき |
|---|---|---|
| Node 22 以上 | `node --version` | 入れる |
| Chromium | `ls ~/.cache/ms-playwright/` に `chromium-*` があるか (Windows: `%LOCALAPPDATA%\ms-playwright`、macOS: `~/Library/Caches/ms-playwright`)。無ければインストール済みの Chrome を使う | `npx playwright install chromium`、または `EV_CHROME=<実行ファイル>` |
| ffmpeg (video だけ) | `ffmpeg -version` | `npm install` で ffmpeg-static が入る。入れられなければ `brew install ffmpeg` / `sudo apt install ffmpeg`、または `EV_FFMPEG=<実行ファイル>` |

`info` / `sheet` / `scene` / `stills` は ffmpeg 無しで動く (コンタクトシートはブラウザ側で並べる)。ffmpeg が要るのは `video` だけ。Playwright 同梱の ffmpeg (`ms-playwright/ffmpeg-*`) は VP8 専用で H.264 が無いので使えない。
フォントは Google Fonts の Noto Sans JP を読み、オフラインならローカルの Noto Sans CJK JP に落ちる。

## 2. テンプレートを作業フォルダにコピー

```bash
mkdir -p <作業フォルダ> && cp -R <このスキルのフォルダ>/assets/template/. <作業フォルダ>/ && cd <作業フォルダ>
npm install                       # playwright-core と ffmpeg-static
node tools/render.mjs info        # 尺と場面の時刻表が出れば動いている
node tools/render.mjs sheet 16    # out/sheet.png を Read で開いて、見本の全体像を見る
```

`npm install` ができない環境 (権限で止められる等) で Playwright がグローバルにあるなら、`mkdir -p node_modules && ln -s "$(npm root -g)/playwright/node_modules/playwright-core" node_modules/playwright-core` で流用できる (ffmpeg は別途)。

書き換えるのは **`data.js` と `timeline.js` だけ**。どちらも完成例が入っているので、上書きする前に書き方の見本として読む。`engine/` は演出を足すときだけ触る。

## 3. 記録を data.js にする

```bash
node tools/record.mjs record.json   # -> data.js (window.RECORD = {...})
```

`timeline.js` では `const R = window.RECORD` として、字幕の数字 (`${R.sentences.length} 文`)、画面の文言、札の名前、棒グラフの値をすべて `R` から引く。手で数字を書かない。

## 4. timeline.js を書く

書式の全項目は `references/timeline.md`、モック画面の部品は `references/screens.md`。

| 記録にあるもの | 場面での表し方 |
|---|---|
| 人が画面でしたこと (貼り付ける、押す、選ぶ) | `ui` 場面。モック画面 + `move` / `type` / `click` / `zoom`。1 場面に操作 1〜2 つ |
| 画面に返ってきたもの (結果、通知) | `ui` 場面。`show` で 1 つずつ出す。必要なら `zoom` で寄る |
| 入力を分ける・数える (文に区切る、項目を抜く) | `mech` 場面。`text` を `split` で `chips` に |
| 点数・件数・順位 | `mech` 場面。`bars` を `show` -> `sort` -> `mark`、`number` を `count` |
| 部品から部品へ渡す (サーバー -> AI -> サーバー) | `mech` の `boxes` + `flow` (1 つの例を運ぶ) か `arch` 場面 (構成の中の該当部分) |
| 誰が誰を呼ぶか、全体の構成 | `arch` 場面。`focus` と `flow` で今の部分だけ光らせる。ノード 3〜6 個 |
| 伝えたい 1 文 | `outro` の `title` |

書き方の決まり:
- **1 場面 1 出来事**。字幕は「何が起きたか」を 1 文 20 字前後 (36px で収まる上限は約 40 字)。説明を足したくなったら、文を足すのではなく `show` / `mark` / 札の名前 / 色で見せられないかを先に考える。
- **役割ごとに色を分ける** (AI / プログラム / 人)。`timeline.js` の先頭で `const AI = '#f59e0b'` のように決め、mech の `color`、arch の `color`、字幕の `color` で揃える。
- **ズームは 1.3〜1.8**。入力中とクリックの瞬間に寄り、終わったら `zoom: 'reset'`。寄りっぱなしにしない。
- **`at` の決め方**: 字幕のタイプが終わる時刻 (文字数 × 0.035 + 0.1 秒) より後に最初の動きを置く。`type` は読む速さより速くてよい (貼り付けの代わりなので `cps: 40` 程度)。出来事の間は 0.4 秒以上あける。
- **モック画面は実物のスクリーンショットを見て作る**。構造と文言を合わせ、色は似ていればよい。`<input>` は使わず `.field` に文字を入れる。スクリーンショットも UI の文言も手に入らないときは、ボタン名や見出しは依頼文にある語をそのまま使い、それ以外は最小限にして、何を仮置きしたかを納品時に伝える。
- **行の並びを 1 つずつ出す**: 札なら `chips`、点数なら `bars`。表のような行は `html` 部品に `data-id` 付きの行を書き、`R.rows.map((r, i) => ({ at: 0.5 + i * 0.3, show: `row${i}` }))` のように events を記録から生成する。
- 同じ画面を 2 つの操作場面で使うなら、状態を引数にした関数で HTML を作る (見本の `screen({ results: true })`)。

## 5. 確かめる (書き出す前に必ず画像で見る)

```bash
node tools/render.mjs info               # 時刻表 (場面の番号と id)
node tools/render.mjs sheet 16           # out/sheet.png 全体を 16 コマ、時刻入り
node tools/render.mjs scene 2 8          # out/scene-2.png その場面だけ 8 コマ (id でも指せる)
node tools/render.mjs stills 6.5,44.9    # out/still-<秒>.png 原寸 1920x1080
```

Read ツールで画像を開いて見る。見るところ:
- コンソールに `data-id not found` / `edge not found` / `unknown` が出ていないか (timeline の id の書き間違い)
- 字幕がはみ出していないか、フォントが効いているか (豆腐や明朝になっていないか)
- 操作の場面: カーソルが押す前にボタンに着いているか、ズームの中心が見せたい要素か、画面の文言が記録と合っているか
- 仕組みの場面: 部品が 730px に収まっているか、札や棒の文字が切れていないか、`mark` が記録の該当 (上位 3 件など) と合っているか。**各場面の終わり近く** (全部が出そろった時刻) を原寸で必ず見る
- 構成図: 線がノードを横切っていないか、光っているノードと粒の向きが字幕と合っているか
- 中身が実データと合っているか (数・答え・処理の名前)。言い換えた文を「」に入れていないか

ブラウザで `index.html` を開くとループ再生、`index.html?t=12.6` でその時刻に止まる (時刻表示つき)。

## 6. 書き出し -> 検証 -> 納品

```bash
node tools/render.mjs video <名前>          # out/<名前>.mp4 + <名前>-poster.png (約 100ms/コマ。60 秒の動画で 3 分強。Bash のタイムアウトを 600 秒にするかバックグラウンドで回す)
node tools/render.mjs video <名前> --gif    # GIF も (15MB 以下になるまで幅と fps を自動で落とす)
FF=$(command -v ffmpeg || node -p "require('ffmpeg-static')")   # ffmpeg-static には ffprobe が無いので ffmpeg -i で代用
"$FF" -i out/<名前>.mp4 2>&1 | grep -E "Duration|Stream"          # 1920x1080 / 30 fps / h264 / yuv420p を確認
# ループ確認: 最初と最後のコマがどちらも背景だけなら継ぎ目なし (最後のコマ番号 = info の frames - 1)
"$FF" -v error -i out/<名前>.mp4 -vf "select='eq(n\,0)+eq(n\,<最後のコマ番号>)',scale=480:-1,tile=2x1" -frames:v 1 -y out/loop-check.png
```

- 1920×1080 / 30fps / H.264 (yuv420p, faststart) なので X・Slack・README (GitHub は MP4 をそのまま再生) にそのまま貼れる。ポスター PNG はサムネイルやブログのアイキャッチに。
- ファイルを渡すツールがあれば MP4 を渡す。作業フォルダをどこに置いたかと、撮り直しの手順 (`record.json` を直す -> `node tools/record.mjs` -> `node tools/render.mjs video`) を伝える。
- ナレーションや BGM は対象外。必要なら書き出した MP4 に ffmpeg で音声を合わせる。

## 専門外の人に見せる中身の書き方

- ファイル名・関数名・JSON の形は出さない。「〜を書いた文章」「〜の一覧」のように中身で呼ぶ。
- 名前を並べるときは何のためのものかを添える (「目次: 困りごとごとに、先に聞くこと」)。
- 判定は「〜か: はい / なし」のように問いと答えの形で書く。
- 実物の文を引くときだけ「」に入れる。短く言い換えたものは「」に入れない。
- 記録に残っていないこと (AI がどう考えたか) は推測で書かない。実際の答えと、それに対応する指示の文を並べる。
- 役割の分担 (AI は判断だけ、処理はプログラム) を伝えたいときは、色分けと締めの一言で見せる。

## 見た目を変えたいとき

- 色・フォント: `timeline.js` に `theme: { bg, card, fg, dim, accent, edge, font, mono }` を足す。明るい背景にするなら `bg` / `card` / `fg` / `edge` をまとめて変える。
- 小見出しの語: `labels: { ui: 'STEP', mech: 'INSIDE' }`。場面ごとに `kicker` を書けばそちらが優先。
- 場面をまたいで見せ続けるもの (履歴の図、地図、進み具合): `TIMELINE.panel` の常時パネル (`references/timeline.md` の panel)。「今どこにいるか」を常に見せたい長めの動画で効く
- 部品にない演出: `kind: 'custom'` の場面で `mount` / `render(lt)` を書く (`references/timeline.md`)。`render` は `lt` だけから絵を決め、`Math.random()` / `Date.now()` / CSS の transition・animation は使わない。
- モック画面の見た目: `screen.html` の中に `<style>` を書いて足す (`references/screens.md`)。

## 実際に踏んだ落とし穴

| 症状 | 原因 | 対処 |
|---|---|---|
| ズームすると白い画面が字幕にかぶって読めない | カメラが舞台全体を拡大していた | カメラの視野を字幕帯を除く 1600×730 に限定 (対処済み。`.clip`) |
| `video` で `ffmpeg exited` / 見つからない | Playwright 同梱の ffmpeg は VP8 専用、システムに ffmpeg が無い | `npm install` (ffmpeg-static) か ffmpeg を入れる。`EV_FFMPEG` でも指定できる |
| `npm install` が権限で止められる | 実行ファイルを取ってくる postinstall が拒否された | グローバルの playwright-core を symlink (手順 2)。ffmpeg は brew / apt で入れる |
| 撮った絵が毎回少しずつ違う | 自前の `<style>` に transition を書いた、`custom` で実時間を使った | 動きはすべて events か `render(lt)` で t から決める |
| `data-id not found: xxx` | timeline の id と HTML の `data-id` が食い違う | `info` のあとコンソールを見て直す。見本の id を流用して消し忘れていないか |
| クリックの前にカーソルが瞬間移動する | 直前の `move` / `click` の終わりが `at - 0.6` より後 | `at` を 0.6 秒以上あける |
| 入力が終わる前に次の出来事が始まる | `type` の所要 = 文字数 ÷ `cps` | `cps` を上げる (貼り付け相当なら 40) か `at` を遅らせる |
| 棒の文字が「…」で切れる | 文が `labelW` (既定 520px) より長い | 文を短くするか `labelW` を広げる、`w` を 1400 に |
| 仕組みの部品が字幕にめり込む | 部品の合計が 730px を超えた | `size` を下げる、`gap` を詰める、場面を 2 つに分ける |
| 結果が出る前にカメラが寄って結果が映らない | `zoom` の中心に寄るので視野の外が切れる | `zoom: { to: ..., scale: 1.3 }` のように倍率を下げる、寄る先を変える、`reset` してから次の操作に |
| 自前 CSS の `opacity` (薄く消す等) が効かない | `show` / `hide` の対象は毎コマ inline の opacity で上書きされる | 薄くするのは子要素 (`.row.out > span { opacity: .3 }`) か色で。`cls` で class を付けて切り替える |
| 判定の前から札の色で結果が分かってしまう | `chips` の `items[].color` は最初から付く | 色は後から `cls` で class を付け、`<style>` で `.chip.ng { --c: #f87171 }` のように上書きする |
| 強調 (`mark`) を付けっぱなしにして画面が重い | 対応を見せたい要素だけ順に光らせるべきところを全部に付けた | 次に移るときに `unmark` する (「いま見る 1 つ」だけ光らせる) |
| ポスターがズームの途中の絵になる | 既定は最初の ui 場面の 1.5 秒後 | `poster: <秒>` で、画面が全部見えている時刻を指定する |
