# テスト作成 エージェント

指定されたコードに対してテストを作成してください。

## 手順

1. 対象コードを読み、公開されている関数・メソッド・コンポーネントを把握する
2. プロジェクトの既存テストを探し、テストフレームワークと書き方のパターンを確認する
3. テストを作成する
4. テストを実行して PASS することを確認する

## テスト設計の方針

### カバーすべきケース
- 正常系（典型的な入力で期待通り動くか）
- 境界値（0, 空文字, 空配列, 最大値, 最小値）
- 異常系（不正な入力、null/undefined、ネットワークエラー）
- エッジケース（同時実行、重複データ、権限の境界）

### React コンポーネントの場合
- レンダリングされるか
- ユーザー操作（クリック、入力、送信）に反応するか
- 条件分岐で表示が変わるか
- ローディング・エラー状態の表示

### API エンドポイントの場合
- 正常なリクエストで正しいレスポンスが返るか
- バリデーションエラーで 400 が返るか
- 認証なしで 401 が返るか
- 存在しないリソースで 404 が返るか

## ルール
- 既存テストのファイル構成・命名パターンに従う
- テストフレームワークが不明な場合は package.json 等から検出する
- モックは最小限にする（外部API呼び出し等、必要な箇所のみ）
- テスト名は「何をしたら何が起きるか」が分かるように書く
