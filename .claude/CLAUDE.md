ユーザへの受け答えは日本語で行ってください。

基本指示がない場合は修正を行わずに修正案までにとどめてください。

npm run devは基本的に使わないでください。

git commit のメッセージに `Co-Authored-By: Claude ...` の行を入れないでください。Claude Code デフォルトの AI トレーラーは付けない方針です。PR/MR 本文の "Generated with Claude Code" 系の自動フッターも同様に付けないでください。

括弧は ASCII の半角 `()` を使ってください。全角 `（）` は混入しやすく、Edit ツールでマッチエラーの原因になります。新規ファイル / 編集箇所では半角で統一してください。既存ファイルが全角の場合は Read 出力をそのままコピペして対処すれば OK です。一括変換が必要なときは `sed -i 's/（/(/g; s/）/)/g' <file>` で。

# セッション状態ファイル

セッション中に方針を採用・却下した、フェーズが進んだ、制約や禁止事項が決まった、といった判断が出た時点で、作業ディレクトリ直下の `.claude-session-state.md` を即座に更新してください (圧縮直前にまとめて書くのではなく、判断のたびに追記する)。このファイルは global gitignore 済みなのでコミットに混ざりません。見出しは次の固定順で保ちます。

1. Active Plan (plan ファイルのパスと現在フェーズ)
2. Tasks (完了 / 進行中 / 未着手)
3. Decisions (採用案、却下案、却下理由)
4. Constraints (順序制約、禁止事項、ブロッカー)
5. Editing Files
6. Recovery Notes (再開時に最初に確認すべきこと)

会話圧縮の直後は、圧縮サマリーを仮説として扱い、plan ファイルとこの状態ファイルを読み直してから作業を再開してください。サマリーと状態ファイルが食い違う場合は状態ファイルを正とします。

書くのは決定・フェーズ・制約が動いたときだけにし、質問に答えただけの回は書きません。状態ファイルが 150 行を超えたら、古い経過を別のファイルに移して今の状態だけにします。

会話を区切る (クリアする) タイミングはこちらから伝えます。開いている作業が片付き、状態ファイルを整理し終えた時点で「クリアして OK」と言います。まだのときは、何が済めばよいかを伝えます。

# Compact instructions

要約時は次を必ず個別の見出しで残してください。
- 採用した方針と、却下した案とその却下理由
- 現在のフェーズと、フェーズの順序制約 (例: 検証が終わるまで配置しない)
- セッション中に決めた制約・禁止事項
- 編集中のファイルと未完了タスク
- `.claude-session-state.md` と plan ファイルのパス
